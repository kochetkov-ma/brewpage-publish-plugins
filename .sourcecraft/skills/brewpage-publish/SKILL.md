# Публикация на BrewPage

Опубликуй `{{ path }}` из этого репозитория на [BrewPage](https://brewpage.app) (бесплатный хостинг HTML, Markdown, файлов и статических сайтов) и верни пользователю ссылку. Аккаунт и API-ключ не нужны. Это переносимая версия навыка [brewpage-publish](https://github.com/kochetkov-ma/claude-brewcode/tree/main/skills/brewpage-publish) (MIT): исходные файлы лежат рядом в `upstream/` как подтверждение происхождения, сам навык их не запускает.

## Перед отправкой

1. Убедись, что `{{ path }}` существует в репозитории. Нет такого пути: остановись и назови его.
2. Публикуй только собранный результат: один файл или папку сайта, где есть `index.html` (или другой HTML-файл, тогда он будет точкой входа). Исходники проекта, `node_modules`, `.git`, `.env`, ключи, токены, пароли и персональные данные не отправляй никогда. Нашёл их в выбранном пути: остановись и перечисли, что мешает.
3. Видимость: `{{ visibility }}`. `public` попадает в галерею BrewPage, карту сайта и поиск: любой найдёт и прочитает. `private` не индексируется, но открывается у любого, у кого есть ссылка.
4. Срок хранения: `{{ ttl }}` дней; пусто: не передавай `ttl`, сервер применит срок по умолчанию. Действующие лимиты: `GET https://brewpage.app/api/limits`.
5. Покажи пользователю, что именно уйдёт: путь, тип, размер (для сайта: список файлов) и видимость.

## Отправка

Один запрос, без повторов. Заголовок `User-Agent: brewpage-sourcecraft/1.0.0 (+https://brewpage.app)` обязателен. Параметры запроса: `ns=public` только при видимости `public` (для `private` параметра `ns` нет), `ttl=<дни>` только если срок задан.

- Один файл (`.html` и `.md` станут страницами, остальные файлы откроются в просмотрщике):

  ```sh
  curl -sS -X POST 'https://brewpage.app/api/files?ns=public&ttl=7' \
    -H 'User-Agent: brewpage-sourcecraft/1.0.0 (+https://brewpage.app)' \
    -F 'file=@docs/report.html'
  ```

- Папка сайта: упакуй её содержимое в ZIP (файлы в корне архива, без скрытых файлов) и отправь архив:

  ```sh
  (cd site && zip -qr -X /tmp/brewpage-site.zip . -x '.*' -x '*/.*')
  curl -sS -X POST 'https://brewpage.app/api/sites?ns=public&ttl=7' \
    -H 'User-Agent: brewpage-sourcecraft/1.0.0 (+https://brewpage.app)' \
    -F 'archive=@/tmp/brewpage-site.zip'
  ```

  Точка входа: `index.html` в корне; иначе добавь `entry=<путь>` к параметрам.

Нет возможности выполнить HTTP-запрос: так и скажи и не придумывай ссылку.

## Результат

Ответ сервера — JSON. Отдай пользователю `link` без изменений, срок `expiresAt` и смысл каждого `notices` (что сервер пометил или опубликовал иначе). `manageUrl` — приватная ссылка управления: кто её получил, тот может изменить или удалить публикацию; `ownerToken` нужен для последующих обновлений.

- В чате Code Assistant отдай `link` и `manageUrl` и один раз предупреди, что ссылка управления приватная. `ownerToken` покажи, если пользователь попросит.
- В CI/CD, где журнал могут читать другие, выведи только `link` и `expiresAt`; `manageUrl` и `ownerToken` в журнал не пиши.
- Никогда не записывай ответ, `manageUrl` или `ownerToken` в репозиторий, предложения изменений, задачи или другие общие каналы.

Ошибка (4xx/5xx): сообщи код и `message` из ответа и остановись. При 429 скажи, через сколько секунд можно повторить (`Retry-After`). Подробности API: https://brewpage.app/llms.txt
